공연 예술 통합 데이터를 활용한 공연 정보 공유 및 리뷰 커뮤니티 플랫폼 Muna 의 UX/UI 디자인과 디자인 시스템 구축을 전담하고 프론트엔드 개발을 담당했습니다.

- **Atomic Design 기반의 컴포넌트 시스템 구축**: 컴포넌트 단위로 UI를 체계적으로 정리하여 개발 과정의 반복적인 수정과 재작업을 최소화하고, 팀원들이 핵심 기능 구현에 몰입할 수 있는 표준화된 개발 환경을 완성했습니다.
- **실무형 WBS 일정 관리 및 병렬 프로세스 주도**: 프로젝트 초기 단계에서 세분화된 WBS를 직접 설계하고 일정을 조율하여, 기획부터 개발 환경 세팅까지 단 1주일 만에 완료하는 효율적인 협업 구조를 이끌었습니다.

## Problem & Solution

Muna는 공연 목록, 검색, 공연 상세, 리뷰, 마이페이지 등
여러 화면과 기능이 연결되는 서비스였습니다.
따라서 개별 화면을 각각 디자인하는 것보다
사용자가 공연을 **발견 → 탐색 → 선택 → 경험을 공유**하는
전체 흐름을 일관된 경험으로 설계하는 것이 중요했습니다.

또한 한 달이라는 제한된 개발 기간 안에
여러 팀원이 동시에 작업해야 했기 때문에,
페이지마다 다른 UI가 만들어지거나
개발 과정에서 반복적인 디자인 수정이 발생하지 않도록
초기 단계에서 공통 UI와 인터랙션 규칙을 정리할 필요가 있었습니다.

1. **사용자 흐름을 기준으로 화면 구조 설계**: 공연 탐색부터 상세 정보 확인, 리뷰 작성까지
   사용자가 주요 기능을 이용하는 흐름을 기준으로
   페이지 구조와 UI를 설계했습니다.

2. **공통 UI를 컴포넌트 단위로 정의**: 버튼, 입력창, 카드 등 반복적으로 사용되는 UI를
   Atomic Design 방식으로 분류하고 Figma에서 공통 컴포넌트와 상태를 정의했습니다.
   이를 통해 화면마다 개별적으로 UI를 제작하는 대신
   동일한 컴포넌트를 조합하여 일관된 인터페이스를 만들 수 있도록 했습니다.

3. **디자인과 개발의 기준을 하나로 통일**: Figma에서 정의한 컴포넌트 구조를
   React의 공통 컴포넌트와 연결했습니다. 디자인 단계에서부터 개발에 필요한 상태와 구조를 고려함으로써
   개발 과정에서 발생할 수 있는 불필요한 UI 재작업을 줄이고자 했습니다.

## 🛠 Challenges & Technical Excellence

### 효율적인 협업을 위한 시스템 가이드 정의

기획 변경이나 UI 수정에 따른 반복적인 재개발을 방지하기 위해 프로젝트 시작 전 **디자인 시스템**을 선제적으로 정의했습니다. **Atomic Design** 패턴에 따라 가장 작은 단위인 버튼, 입력창부터 복잡한 카드 형태까지 체계적으로 설계하였으며, 이를 코드 단의 **공통 컴포넌트**와 동기화했습니다.

이러한 설계 덕분에 개발 중 UI 수정 비용을 획기적으로 낮출 수 있었고, UI 디자인 결과물이 코드에 즉각적으로 반영되어 높은 디자인 완성도를 유지할 수 있었습니다. 이는 팀원들이 복잡한 레이아웃 고민 없이 기능 구현에만 집중할 수 있는 튼튼한 기반이 되었습니다.

### API 제약사항을 극복한 데이터 및 상태 관리

Kopis Open API가 최신순 정렬 등 필수적인 기능을 제공하지 않는 한계를 파악하고, 이를 **Firestore DB**와 **Redux Toolkit**으로 보완하는 아키텍처를 설계했습니다. `createAsyncThunk`를 활용해 Firebase와의 비동기 통신을 전역 상태로 관리하며, API가 제공하지 못하는 정렬 로직을 프론트엔드 단에서 안정적으로 구현했습니다.

또한, **Firebase Emulator**를 도입하여 로컬 환경에서도 클라우드 서비스와 동일한 환경을 구축함으로써 데이터 연동 오류를 사전에 차단하고 개발 생산성을 높였습니다.

## 📊 Results & Lessons Learned

프론트엔드 부트캠프 과정이었기에 개발 구현이 중심이었지만, 완성도 높은 프로덕트를 만들기 위해 디자인 단계부터 치밀하게 접근했습니다. 추후 UI 수정과 재작업을 최소화하기 위해 팀원들이 다소 과하다 느낄 정도로 초기 단계에서 **컴포넌트 단위의 견고한 디자인 시스템과 UI 구조를 설계**했습니다. 그 덕분에 기획과 디자인 수정으로 인한 낭비를 줄이고, 한 달이라는 짧은 기간 내에 핵심 프론트엔드 개발에 완전히 몰두할 수 있는 최적의 환경을 만들 수 있었습니다.

팀에서 실무 경험이 가장 많았던 멤버로서, **세분화된 WBS 설계 등 전체적인 일정과 프로세스를 주도적으로 관리**했습니다. 체계적인 디자인 시스템과 협업 프로세스를 구축한 점을 인정받아 최종 심사에서 우수수료생 선정 및 프로젝트 최우수상을 수상하며 실무 수준의 역량을 검증받았습니다.

이 프로젝트는 늘 어렵게만 느껴졌던 프론트엔드를 기초부터 다지고 실제 서비스로 구현해낸 소중한 도전이었습니다. 늦은 시작이었지만 새로운 것에 도전하고 배우며 성장하는 즐거움을 깨달았고, 스스로에 대한 깊은 자신감을 얻을 수 있었던 의미 있는 성장의 기점이었습니다.
