웹사이트를 만들 때 SEO(Search Engine Optimization, 검색엔진 최적화)는 특정 단계에서 한 번 적용하고 끝나는 작업이 아닙니다.
검색엔진이 페이지의 내용을 제대로 이해할 수 있도록 구조를 설계하고, 사용자가 콘텐츠를 편리하게 이용할 수 있도록 만들며, 페이지가 빠르고 안정적으로 제공되도록 하는 과정 전반에 걸쳐 SEO를 고려할 수 있습니다.

디자인부터 퍼블리싱, 프론트엔드, 백엔드까지 각 역할에서 바라보는 SEO는 조금씩 다릅니다.
이 글에서는 SEO가 무엇인지 간단히 정리하고, 웹 서비스를 만드는 각 단계에서 어떤 부분을 고려할 수 있는지 살펴봅니다.

---

## SEO란?

SEO는 **Search Engine Optimization**, 즉 검색엔진 최적화를 의미합니다.

검색엔진이 웹페이지의 콘텐츠와 구조를 잘 이해하고, 사용자가 검색했을 때 관련성이 높은 페이지를 적절하게 노출할 수 있도록 웹사이트를 개선하는 작업입니다.
단순히 검색 결과에서 높은 순위를 얻기 위해 키워드를 반복해서 넣는 것이 SEO의 전부는 아닙니다.

검색엔진이 페이지를 발견하고,

> 이 페이지에는 어떤 콘텐츠가 있는가?

를 이해할 수 있어야 하고,

사용자 역시

> 내가 찾던 정보가 이 페이지에 있는가?

를 빠르게 확인할 수 있어야 합니다.

따라서 SEO는 크게 보면 **검색엔진을 위한 최적화이면서 동시에 사용자를 위한 웹페이지를 만드는 과정**이라고 볼 수 있습니다.

---

## SEO는 한 사람의 일이 아니다

SEO를 마케팅이나 콘텐츠 담당자의 업무로만 생각하기 쉽지만, 실제 웹페이지가 검색엔진에 잘 노출되기 위해서는 여러 영역이 함께 작동해야 합니다.

예를 들어 하나의 상품 상세 페이지가 있다면,

- 디자인 단계에서는 콘텐츠의 우선순위와 정보 구조를 정하고,
- 퍼블리싱 단계에서는 이를 의미 있는 HTML 구조로 구현합니다.
- 프론트엔드에서는 메타 정보나 라우팅, 렌더링 방식을 관리하고,
- 백엔드에서는 검색엔진이 접근할 수 있는 안정적인 데이터와 URL 구조, 서버 응답 환경 등을 구성할 수 있습니다.

즉 SEO는 특정 직군의 단독 업무라기보다 **웹을 만드는 각 단계가 연결되어 만들어지는 결과**에 가깝습니다.

---

# 1. 디자인 관점의 SEO

SEO라고 하면 HTML이나 서버를 먼저 떠올리기 쉽지만, 그보다 앞선 디자인 단계에서도 중요한 결정이 이루어집니다.

### 콘텐츠의 우선순위를 명확하게 만들기

검색엔진이 페이지의 내용을 이해하려면 페이지 안에 무엇이 중요한지 명확해야 합니다.
따라서 디자인 단계부터 **정보의 위계를 명확하게** 구성하는 것이 좋습니다.

예를 들어 상품 상세 페이지라면,

- 상품명
- 상품의 핵심 특징
- 가격
- 구매 정보
- 상세 설명
- FAQ

등의 콘텐츠가 어떤 순서와 중요도로 제공되어야 하는지 결정할 수 있습니다.
이러한 정보 구조는 이후 HTML의 제목 계층이나 콘텐츠 구조에도 영향을 줍니다.

### 텍스트를 이미지로만 표현하지 않기

디자인적으로 텍스트를 이미지 안에 넣는 것이 더 깔끔해 보이는 경우가 있습니다.
하지만 중요한 정보를 이미지 안에만 넣으면 검색엔진이 콘텐츠를 이해하기 어려워질 수 있고, 사용자의 접근성도 떨어질 수 있습니다.

따라서 검색되어야 하는 중요한 정보는 가능한 한 실제 텍스트 콘텐츠로 제공하는 것이 좋습니다.

물론 모든 텍스트를 이미지로 만들면 안 된다는 의미는 아닙니다.
브랜드 로고나 장식적인 그래픽처럼 이미지 자체가 필요한 경우도 있기 때문에, **어떤 정보가 반드시 텍스트로 전달되어야 하는지 판단하는 것**이 중요합니다.

### 모바일 환경 고려하기

검색엔진뿐 아니라 실제 사용자의 환경을 고려하는 것도 중요합니다.
모바일에서 콘텐츠가 지나치게 작거나, 버튼을 누르기 어렵거나, 중요한 정보가 화면 밖으로 밀려난다면 사용성이 떨어집니다.

따라서 디자인 단계에서부터 반응형 환경과 콘텐츠의 가독성, 인터랙션 등을 고려해야 합니다.

SEO를 단순히 검색엔진만을 위한 작업으로 생각하지 않고 **사용자가 콘텐츠를 잘 소비할 수 있는 환경을 만드는 것**으로 바라보면 디자인 단계에서도 자연스럽게 연결됩니다.

# 2. 퍼블리싱 관점의 SEO

퍼블리싱 단계에서는 SEO와 직접적으로 연결되는 부분이 많습니다.
가장 중요한 것은 **의미 있는 HTML 구조를 만드는 것**입니다.

## 시맨틱 HTML

HTML에는 각 요소가 어떤 역할을 하는지 표현할 수 있는 다양한 태그가 있습니다.

```html
<header>
  <nav>...</nav>
</header>

<main>
  <article>
    <h1>웹 퍼블리싱이란?</h1>

    <section>
      <h2>퍼블리싱의 역할</h2>
      <p>...</p>
    </section>
  </article>
</main>

<footer>...</footer>
```

모든 영역을 `div`로 만들 수도 있지만, 콘텐츠의 의미에 맞는 HTML 요소를 사용하면 브라우저와 검색엔진, 보조기기 등이 문서 구조를 이해하는 데 도움이 됩니다.

특히 제목은 단순히 글자를 크게 보이게 하기 위한 용도가 아니라 **콘텐츠의 계층을 표현하는 요소**로 사용하는 것이 좋습니다.

```html
<h1>웹 퍼블리싱</h1>
<h2>HTML</h2>
<h2>CSS</h2>
<h2>반응형 웹</h2>
```

CSS로 크기를 조절하기 위해 `h1`, `h2` 등을 선택하는 것이 아니라, 실제 문서 구조에 맞춰 사용하는 것이 핵심입니다.

---

## title과 meta description

페이지의 `<head>` 영역도 SEO에서 중요한 역할을 합니다.

```html
<title>웹 퍼블리싱 강의 | ABC 아카데미</title>

<meta
  name="description"
  content="HTML과 CSS를 활용한 웹 퍼블리싱 기초부터 실습까지 배우는 과정입니다."
/>
```

`title`은 페이지의 제목을 나타내며 검색 결과나 브라우저 탭 등에 활용됩니다.

`meta description`은 페이지의 내용을 간결하게 설명하는 정보로, 검색 결과에서 사용자에게 페이지의 내용을 이해시키고 클릭을 유도하는 데 도움을 줄 수 있습니다.

다만 meta description을 작성한다고 해서 검색 순위가 직접적으로 올라가는 것은 아닙니다.

---

## 이미지와 alt

이미지를 사용할 때는 적절한 대체 텍스트를 제공하는 것도 중요합니다.

```html
<img src="/images/publishing-course.jpg" alt="웹 퍼블리싱 실습 화면" />
```

`alt`는 이미지가 표시되지 않을 때의 대체 텍스트이면서, 스크린 리더가 이미지의 내용을 전달할 때도 사용됩니다.

단순히 SEO를 위해 키워드를 넣는 것이 아니라 **이미지의 실제 의미를 설명하는 것**이 중요합니다.

장식용 이미지처럼 별도의 정보가 없는 경우에는 빈 `alt`를 사용할 수도 있습니다.

```html
<img src="/images/deco.png" alt="" />
```

---

## 의미 있는 링크 만들기

링크의 텍스트 역시 콘텐츠의 의미를 전달할 수 있습니다.

```html
<a href="/courses/publishing"> 웹 퍼블리싱 강의 </a>
```

단순히

```html
<a href="/courses/publishing"> 자세히 보기 </a>
```

라고 작성하는 것보다 링크가 어떤 페이지로 연결되는지 알 수 있는 텍스트를 사용하는 것이 사용자와 검색엔진 모두에게 더 명확할 수 있습니다.

---

# 3. 프론트엔드 관점의 SEO

프론트엔드에서는 단순한 HTML 구조뿐 아니라 **페이지가 어떻게 렌더링되고, URL과 메타 정보가 어떻게 관리되는지**도 고려할 수 있습니다.

## SSR과 SSG

React와 같은 프레임워크를 사용하면 페이지의 콘텐츠를 브라우저에서 동적으로 렌더링하는 경우가 있습니다.

이때 검색엔진이 페이지 콘텐츠를 안정적으로 발견하고 이해할 수 있도록 렌더링 방식을 적절하게 선택하는 것이 중요합니다.

Next.js와 같은 프레임워크에서는 다음과 같은 렌더링 방식을 사용할 수 있습니다.

- SSR(Server-Side Rendering)
- SSG(Static Site Generation)
- ISR(Incremental Static Regeneration)
- CSR(Client-Side Rendering)

모든 페이지에 하나의 방식을 적용하는 것이 아니라 페이지의 특성에 따라 적절한 방식을 선택하는 것이 중요합니다.

예를 들어 검색 결과에 노출되어야 하는 블로그나 상품 상세 페이지는 서버에서 콘텐츠가 준비된 상태로 전달되는 방식을 고려할 수 있습니다.

반면 로그인 이후 사용하는 관리자 페이지처럼 검색엔진에 노출될 필요가 없는 페이지라면 SEO보다 애플리케이션의 사용성과 기능에 집중할 수 있습니다.

---

## 페이지별 메타데이터 관리

SPA나 프레임워크를 사용하는 경우 페이지마다 적절한 메타데이터를 제공하는 것도 중요합니다.

예를 들어 Next.js에서는 페이지에 맞춰 title과 description 등을 설정할 수 있습니다.

```tsx
export const metadata = {
  title: "웹 퍼블리싱 강의",
  description: "HTML과 CSS를 활용한 웹 퍼블리싱 실습 과정입니다.",
};
```

하나의 사이트에서 모든 페이지가 동일한 title과 description을 사용하는 것보다 **각 페이지의 콘텐츠를 정확하게 설명하는 메타데이터를 제공하는 것**이 좋습니다.

---

## URL 구조

URL 역시 웹페이지의 구조와 콘텐츠를 이해하는 데 도움을 줄 수 있습니다.

```text
/courses/publishing
/courses/frontend
/blog/seo-guide
```

처럼 의미를 파악할 수 있는 구조가

```text
/page?id=123
```

처럼 의미를 알기 어려운 URL보다 사용자에게도 이해하기 쉽습니다.

URL을 설계할 때는 사이트의 정보 구조와 함께 일관성 있게 구성하는 것이 중요합니다.

---

## 웹 성능

웹페이지의 성능 역시 SEO와 사용자 경험 측면에서 중요합니다.

예를 들어 다음과 같은 작업을 할 수 있습니다.

- 이미지 최적화
- 불필요한 JavaScript 제거
- CSS 최적화
- 코드 스플리팅
- 적절한 캐싱
- 폰트 로딩 최적화
- 레이지 로딩
- 레이아웃 이동 최소화

특히 사용자가 실제로 페이지를 얼마나 빠르고 안정적으로 이용할 수 있는지는 중요한 웹 품질 요소입니다.

따라서 프론트엔드에서는 **검색엔진에 잘 보이는 페이지뿐 아니라 사용자가 빠르게 이용할 수 있는 페이지**를 만드는 것도 SEO의 중요한 일부로 볼 수 있습니다.

---

# 4. 백엔드 관점의 SEO

백엔드는 사용자에게 직접 보이지 않기 때문에 SEO와 거리가 있어 보이지만, 검색엔진이 웹사이트에 접근하고 콘텐츠를 가져가는 과정에서 중요한 역할을 합니다.

## 크롤링을 고려한 서버 환경

검색엔진은 웹사이트의 URL을 따라가면서 페이지를 수집합니다.

따라서 서버에서 페이지가 안정적으로 응답되어야 합니다.

예를 들어 존재하지 않는 페이지는 적절하게 `404` 상태 코드를 반환하고, 정상적인 페이지는 `200` 상태 코드를 반환하는 등 HTTP 상태 코드를 올바르게 사용하는 것이 중요합니다.

---

## sitemap.xml

사이트의 페이지 구조를 검색엔진에 알려주는 `sitemap.xml`을 제공할 수도 있습니다.

예를 들어:

```xml
<urlset>
  <url>
    <loc>https://example.com/</loc>
  </url>

  <url>
    <loc>https://example.com/blog/seo</loc>
  </url>
</urlset>
```

사이트에 많은 페이지가 있거나 콘텐츠가 지속적으로 생성되는 서비스라면 사이트맵을 적절하게 관리하는 것이 도움이 될 수 있습니다.

---

## robots.txt

`robots.txt`를 통해 검색엔진 크롤러에게 특정 경로에 대한 크롤링 정책을 전달할 수도 있습니다.

```text
User-agent: *
Disallow: /admin/
```

관리자 페이지처럼 검색엔진에 노출할 필요가 없는 영역은 크롤링 대상에서 제외하는 식으로 활용할 수 있습니다.

다만 `robots.txt`는 페이지를 검색 결과에서 완전히 제거하기 위한 보안 수단은 아닙니다.

민감한 정보를 robots.txt로 보호해서는 안 되며, 인증이나 접근 제어가 필요한 데이터는 서버에서 별도로 보호해야 합니다.

---

## 구조화된 데이터

백엔드 또는 프론트엔드에서 페이지의 콘텐츠를 구조화된 데이터로 제공할 수도 있습니다.

대표적으로 Schema.org 기반의 JSON-LD를 사용할 수 있습니다.

예를 들어 상품이라면 상품명, 가격, 재고 등의 정보를 검색엔진이 이해할 수 있는 형태로 제공할 수 있습니다.

```json
{
  "@context": "https://schema.org",
  "@type": "Product",
  "name": "웹 퍼블리싱 강의",
  "description": "HTML과 CSS를 활용한 웹 퍼블리싱 강의"
}
```

이 역시 검색 순위를 직접적으로 보장하는 방법이라기보다 **검색엔진이 콘텐츠를 더 구조적으로 이해하도록 돕는 방법**이라고 보는 것이 적절합니다.

# SEO는 결국 연결되어 있다

각 영역을 나누어 보면 SEO를 위해 해야 할 일이 달라 보입니다.

| 영역       | 주요 고려 사항                              |
| ---------- | ------------------------------------------- |
| 디자인     | 정보 구조, 콘텐츠 우선순위, 가독성, 반응형  |
| 퍼블리싱   | 시맨틱 HTML, 제목 구조, alt, 링크 구조      |
| 프론트엔드 | 렌더링, 메타데이터, URL, 성능               |
| 백엔드     | HTTP 응답, sitemap, robots.txt, 데이터 구조 |

하지만 실제 웹사이트에서는 이 요소들이 서로 연결되어 있습니다.

예를 들어 검색엔진에 잘 노출되는 블로그를 만든다고 생각해보겠습니다.

디자이너가 콘텐츠의 계층을 잘 설계하고,

퍼블리셔가 이를 `h1`, `h2`, `article` 등의 의미 있는 HTML로 구현하고,

프론트엔드에서 페이지별 metadata와 적절한 렌더링 방식을 적용하고,

백엔드에서 안정적인 응답과 URL, sitemap 등을 제공해야 합니다.

어느 한 단계만 잘한다고 완성되는 것이 아닙니다.

# SEO를 위해 가장 먼저 해야 할 것

SEO를 처음 접한다면 복잡한 기술부터 적용하기보다 기본적인 웹의 구조부터 점검하는 것이 좋습니다.

### 1. 검색되어야 하는 콘텐츠가 실제 텍스트로 존재하는가?

이미지 안에만 중요한 정보를 넣고 있지는 않은지 확인합니다.

### 2. HTML 구조가 콘텐츠의 의미를 제대로 표현하고 있는가?

`div`를 무조건 사용하는 대신 적절한 시맨틱 요소를 사용합니다.

### 3. 페이지마다 제목과 설명이 적절한가?

`title`, `description` 등을 페이지의 콘텐츠에 맞게 구성합니다.

### 4. 검색엔진이 페이지를 제대로 크롤링할 수 있는가?

URL, 내부 링크, sitemap, robots.txt, HTTP 상태 코드 등을 확인합니다.

### 5. 사용자가 빠르고 편리하게 이용할 수 있는가?

이미지와 리소스를 최적화하고 모바일 환경과 웹 성능을 함께 고려합니다.

# 마무리

SEO를 공부하면서 처음에는 검색 결과의 순위를 높이는 기술이라고 생각하기 쉽습니다.

하지만 웹을 직접 만들다 보면 SEO는 특정 기술 하나로 해결되는 문제가 아니라는 것을 알게 됩니다.

**검색엔진이 이해하기 쉬운 구조를 만들고, 사용자가 원하는 정보를 찾기 쉽게 만들고, 빠르고 안정적으로 콘텐츠를 제공하는 것.**

결국 좋은 SEO는 좋은 웹을 만드는 과정과 상당 부분 겹쳐 있습니다.

그래서 SEO를 특정 직군의 업무로 한정하기보다는,

> **디자인에서 콘텐츠를 구조화하고,  
> 퍼블리싱에서 의미 있는 HTML을 만들고,  
> 프론트엔드에서 콘텐츠와 성능을 최적화하고,  
> 백엔드에서 검색엔진이 안정적으로 접근할 수 있는 환경을 만드는 것.**

이렇게 웹을 만드는 전체 과정의 관점에서 바라보는 것이 중요하다고 생각합니다.
