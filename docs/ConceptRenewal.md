# 컨셉 리뉴얼 기획: "나의 선반과 벽"

> **브랜치:** `feat/shelf-concept` (기존 `main`은 건드리지 않는다)
> **상태:** 기획 개정본(4차). 선반 비주얼, 확정 사항(대표 프로젝트 `featured` 통일, 크림 톤 전환, 선반 2단, 대표 2개는 액자, 정돈 상태로 시작)을 반영했다. 구현은 아래 Phase 순서대로 진행한다.

## 1. 한 줄 요약

기존 `Hero` 영역을 **"내 공간" 장면**으로 대체한다. 벽에는 프로젝트 폴라로이드가 붙어 있고, 2단 선반 위에는 나를 설명하는 물건 3개와 가장 메인인 프로젝트 2개를 담은 액자가 놓여 있다. 처음에는 모두 정돈된 상태이고, 방문자는 물건과 사진을 드래그해 마음대로 어지르거나 정돈 버튼으로 되돌릴 수 있으며, 눌러서 내 정보를 열어볼 수 있다. 메인에는 `featured` 대표 프로젝트만 보여준다(4~6개 이내). 기존의 깔끔한 스타일은 이 컨셉에 맞춰 바꾸거나 과감히 뺀다.

분위기 키워드: 손에 잡히는 질감, 따뜻함, 여백, 장난스러움, 개인적인 이야기.

## 3. 레퍼런스 분석

### 3-1. jackiehu.design: 메인 아이템 비주얼, 표현, 배치 방식 (스크린샷 기반)

스크린샷 두 장은 같은 메인 화면의 **서로 다른 상태**다.

| | 상태 A: 정돈 | 상태 B: 겹쳐 쌓인 콜라주 |
|---|---|---|
| 배치 | 물건이 화면 전체에 여백을 두고 흩어져 있음. 이름은 오른쪽 정렬 | 물건이 왼쪽 위/아래, 오른쪽 가장자리에 겹쳐 쌓임. 서로 겹치고 기울어져 있음. 이름은 정중앙 |
| 하단 버튼 | 빗자루 버튼이 선택됨 | 커피컵 버튼이 선택됨 |

- 하단 중앙의 아이콘 버튼 3개(커피컵, 빗자루, 연필)는 **배치 상태를 바꾸는 컨트롤**로 보인다. 빗자루 = 정돈, 커피컵 = 어질러진 콜라주는 스크린샷으로 확인된다. 연필 버튼의 동작은 스크린샷만으로는 알 수 없다.
- 물건은 배경이 제거된 사진 컷아웃이며 **같은 크림색 단색 배경, 은은한 그림자**를 공유한다. 램프, 약상자, 찢긴 사전 조각, 필름, 라이터, 노트(커피 자국), 튜브, 펜 등 취향과 일상을 보여주는 물건들이다.
- 사진 오브젝트에 UI 오브젝트(AirDrop 카드, 폴더 "Final_Final_Final", 그림판 툴바, 픽셀 커서)를 섞어 직업 정체성을 표현한다.
- 음악 플레이어 카드의 재생 시간이 두 스크린샷에서 다르다(1:21 → 1:30). 장식이 아니라 **실제로 움직이는 위젯**이다.
- 이름은 필기체, 소개 문구는 모노스페이스로 대비를 준다.
- **적용:** 두 상태 중 **정돈 상태로 시작**하고, 어질러진 상태는 방문자가 드래그로 직접 만든다. 레퍼런스의 빗자루 버튼처럼 **정돈 버튼**을 한쪽에 둔다. 가만히 있는 이미지만 두지 않고 "조금씩 살아 있는" 요소(시간이 가는 위젯 등)를 하나쯤 둘지는 Phase 5에서 검토한다.

> 위 설명은 스크린샷과 페이지 텍스트 기준이다. 드래그 여부, 전환 모션, 연필 버튼의 동작은 실제 사이트에서 확인한다.

## 4. 메인 Hero 설계

### 4-1. 공간과 선반 비주얼

**참고 이미지 3장에서 가져올 것**

| 이미지 | 특징 | 채택 여부 |
|---|---|---|
| 1. 검은 브래킷 2단 선반 | 오렌지 브라운 선반 판, 검은 금속 지지대, 책/화분/액자의 높낮이 있는 연출 | 지지대는 **제외**. 물건의 높낮이를 다르게 두는 연출만 참고 |
| 2. 자연 가장자리 플로팅 2단 선반 | 코르크 느낌의 결, 벽에 떠 있는 선반, 선반 아래 부드러운 그림자, 화분/액자/소품의 여백 있는 배치 | 플로팅 형태와 그림자, 여백 연출을 참고 |
| 3. 월넛 플로팅 3단 선반 | 두꺼운 판 하나뿐인 깔끔한 형태, 선명한 나뭇결, 크림 벽, 판 아래 은은한 그림자 | **기준 스타일** |

**선반 스펙 (3번 이미지 기준)**
- 선반은 **두꺼운 나무 판 하나**다. 세로선(지지대), 브래킷, 밑 받침 등 다른 구조물은 그리지 않는다. 벽에 떠 있는 플로팅 형태.
- 시점은 정면. 판의 앞면(두께)이 보이고, 윗면은 얇은 하이라이트 선으로만 표현한다. **물건의 바닥은 이 윗면 선에 닿는다.** 이 선의 y좌표가 물건이 떨어져 멈추는 바닥이다.
- 색은 월넛 계열의 따뜻한 브라운, 나뭇결이 보이는 질감. 판 아래 벽에 부드러운 그림자를 깐다.
- 벽은 단색에 가까운 따뜻한 크림(3번 이미지의 벽처럼 아주 약하게 명암이 있는 오프화이트).
- 물건은 높이는 조금씩 다르게 하되 **크기는 비슷한 범위로 맞춘다**(가장 큰 물건이 선반 간격의 절반 안팎을 넘지 않게). 액자만 "가장 메인"이므로 조금 더 크게 둔다. 겹치지 않게 여백을 두고 배치한다(1·2번 이미지처럼). 물건 아래에는 판 위에 닿는 접촉 그림자를 둔다.
- **2단 선반**으로 구성한다. 물건과 액자가 위아래 판 사이를 오가며 놀 수 있다. 판의 길이와 위치는 Phase 4에서 장면 비율을 보고 정한다.

**장면 구성 초안** (정돈 상태, 배치는 제안)
```
┌───────────────────────────────────────────────┐
│  [폴라로이드 3장, 벽에 붙음]      이름 / 소개 / CTA │
│                                               │
│   ┌액자┐ ┌액자┐         🪴 스킨답서스             │
│  ━━━━━━━━━━━━ 상단 선반 (판대기만) ━━━━━━━━━━━━  │
│                                               │
│        🧶 실뭉치        🧴 핸드크림              │
│  ━━━━━━━━━━━━ 하단 선반 (판대기만) ━━━━━━━━━━━━  │
│                                  [🧹 정돈] [목록] │
└───────────────────────────────────────────────┘
```
- 이름/타이틀/소개 문구는 장면 안의 텍스트 레이어로 두고 `h1`은 유지한다.
- 모든 물건 이미지는 조명 방향, 각도, 그림자 톤을 통일한다.

### 4-2. 아이템 구성

| 아이템 | 위치(제안) | 눌렀을 때 열리는 내용 | 기존 코드/데이터 |
|---|---|---|---|
| 실뭉치 | 하단 판 위 | **커리어 로드맵** (타임라인) | `data/timelineData.ts`, `Timeline.tsx`의 소개 문단 재사용 |
| 핸드크림 (튜브) | 하단 판 위 | **기술 스택 + 소프트스킬** | `Skill.tsx`의 `skillGroups` 재사용. 소프트스킬 항목은 새로 정리 필요 |
| 스킨답서스 화분 | 상단 판 위 | **자기소개서** | 새 텍스트 필요. `Timeline.tsx` 좌측 문단과 Hero 소개 문구를 초안 재료로 사용 |
| 액자 2개 | 상단 판 위(벽에 기대어 세움) | **가장 메인인 프로젝트 2개** (클릭 → 프로젝트 상세) | `projectsData`의 `featured.order` 상위 2개 |
| 폴라로이드 3개 | 벽 | **나머지 대표 프로젝트 3개** (클릭 → 프로젝트 상세) | `projectsData`의 `featured` 나머지 |

물건 3개, 액자 2개가 2단 선반에 나뉘고 벽에는 폴라로이드 3장만 붙으므로 장면이 복잡해지지 않는다. 판별 배치는 Phase 4에서 조정한다.

**핸드크림으로 정한 이유:** 처음 안이던 맥북프로는 다른 물건에 비해 너무 커서 선반을 지배한다. 핸드크림 튜브는 실뭉치, 화분과 크기가 비슷하고, 말랑한 튜브라 스쿼시 앤 스트레치도 잘 어울린다. 손으로 일하는 사람의 물건이라 "기술(손에 익은 도구)"과도 자연스럽게 연결된다. 대안으로는 꽃병이 있으나 스킨답서스와 식물 계열이 겹쳐 기본안에서는 제외했다(열린 질문 참고).

### 4-3. 폴라로이드와 액자 상세

**폴라로이드 (벽, 3개)**
- 벽에 붙은 구성. 프레임은 **CSS/SVG로 만든다**(AI 이미지 불필요). 사진 영역에 프로젝트 이미지, 하단 여백에 **프로젝트 키워드를 손글씨체**로 넣는다.
- 사진 이미지는 기존 `public/projects/*/thumb.png`(800×520 가로형)나 `mockup.png`(약 1089×1080 ~ 1200×938)를 재사용할 수 있다. 폴라로이드는 정사각에 가까우므로 `object-fit: cover` 크롭으로 충분한지 확인하고, 부족하면 폴라로이드용 이미지 필드를 추가한다.
- 데이터 확장 제안: `projectsData` 항목에 `polaroid?: { image: string; keyword: string; rotate?: number }` 추가. 또는 별도 파일 `data/shelfItems.ts`에서 프로젝트 id와 키워드를 매핑.
- 손글씨 폰트는 한글 지원 필요. 후보를 정해 `next/font`로 로드한다(예: Nanum Pen Script, Gaegu 등. 최종 선택은 Phase 1에서).
- 약간씩 다른 기울기, 테이프/핀 같은 작은 고정 표현, 그림자로 "벽에 붙은" 느낌을 준다.

- **키워드 초안**(`featured` 5개 중 폴라로이드 3개에 사용. 액자 2개는 선택적으로 작은 프로젝트명 라벨만. 프로젝트 데이터 기준 초안이며 내용 확인 후 수정):

| 프로젝트 | 키워드 초안 |
|---|---|
| rounz | AI 가상 피팅 / Admin 개편 |
| muna | 공연 리뷰 커뮤니티 / 디자인 시스템 |
| chromatic | 블록체인 트레이드 UI |
| klaybay | 마켓플레이스 / 반응형 |
| miral-payment | 결제 리뉴얼 / UX 개선 |

**액자 (선반, 2개)**
- 2번 이미지처럼 **선반 판 위에 벽에 기대어 세운** 액자. 프레임은 CSS로 만든다(얇은 프레임 + 안쪽 여백 + 프로젝트 이미지). AI 이미지는 필요 없다.
- 프로젝트 이미지는 `featured.cover`(`mockup.png`, 약 1089×1080 ~ 1200×938)를 쓴다. 정사각에 가까워 액자에 잘 맞고, 폴라로이드보다 크게 보여 "가장 메인" 느낌을 준다.
- 약간 기울인 채 기대어 선 느낌(1~3도), 바닥에 닿는 접촉 그림자를 준다.
- 프레임 색은 월넛(선반과 맞춤) / 블랙(2번 이미지) / 얇은 화이트 중에서 Phase 1에서 확정.

### 4-4. 정돈 상태와 어지르기
- 첫 화면은 **정돈된 상태**다. 아이템마다 정돈 위치(`home`: x, y, rotate)만 정의한다.
- **어지르기:** 별도 버튼 없이 방문자가 드래그앤드롭으로 직접 만든다. 선반 위 물건과 액자는 놓은 곳에서 떨어지고, 폴라로이드는 놓은 곳에 붙는다.
- **정돈 버튼:** 화면 한쪽에 둔다(기본 우하단, 레퍼런스의 빗자루 아이콘 참고). 누르면 모든 아이템이 spring으로 각자의 `home` 위치로 돌아간다(선반 위 물건은 통통, 폴라로이드는 슥 붙는 느낌). 이미 정돈된 상태면 비활성 처리한다.
- **목록으로 보기:** 정보만 빠르게 보고 싶은 사람(채용 담당자)을 위한 대체 뷰. 같은 데이터로 렌더링하며 정돈 버튼 옆에 작게 둔다.
- 위치는 저장하지 않는다. 새로고침하면 항상 정돈 상태로 시작한다(열린 질문 7의 기본안).
- 입장 애니메이션이 끝나면 정돈 상태로 안착한다.

### 4-5. 인터랙션 (벽과 선반의 물리 규칙을 다르게)
- **선반 위 물건:** 드래그해서 놓으면 중력으로 **판 윗면 선(4-1의 바닥 y)**까지 spring으로 떨어지고, 착지 순간 **스쿼시 앤 스트레치**(납작해졌다 튕김). 놓은 x 위치 바로 아래에 판이 있으면 그 판에, 판이 없으면 가장 가까운 아래 판에 앉는다. 판 가로 범위를 벗어나지 않게 제한한다. 물건별 `softness`로 강도를 다르게 한다(실뭉치/식물 잎/튜브는 말랑, 액자는 거의 안 찌그러짐).
- **액자:** 선반 위 물건과 같은 낙하 규칙을 따르되 단단한 물건이므로 `softness`를 0에 가깝게 둔다(찌그러짐 없이 착지 순간 아주 짧게 흔들림). 기대어 선 기울기는 유지한다.
- **벽 위 폴라로이드:** 떨어지지 않는다. 드래그한 위치에 **붙어 있고**, 놓을 때 살짝 기울어지며 안착한다. 집어든 사진은 맨 앞(z-index)으로 올라온다.
- **클릭:** 이동 거리 임계값으로 드래그와 클릭을 구분한다. 물건 클릭 시 정보 패널(모달/시트)이 열리고, 폴라로이드 클릭 시 프로젝트 상세로 이동한다.
- 구현은 framer-motion(`drag`, `dragConstraints`, spring)으로 시작한다. 선반 낙하가 부족하면 Matter.js 추가를 검토한다.
- 입장 애니메이션: 기존 Hero의 "세션당 한 번 재생" 방식을 참고해, 첫 방문 때 물건이 툭 떨어지며 입장하게 한다.

### 4-6. Hero 대체 방식
- 새 컴포넌트 `ShelfHero`를 만들고 `Home.tsx`의 `<Hero />` 자리에 교체한다. 기존 `Hero.tsx`는 **삭제하지 않고** 비교용으로 남긴다.
- `GradientMesh`, `MainAnimation`은 Hero에서만 쓰이므로 교체 후 미사용이 된다. 삭제 여부는 마지막에 결정한다.
- 기존 Hero의 문구(타이틀, 소개 문구)와 CTA(`/projects` 이동)는 새 장면 안에서 유지한다.
- `section`은 `h-screen` 대신 모바일 주소창을 고려해 `100svh` 기준으로 잡는다.
- `HeroContext`의 `visited`는 현재 `Hero.tsx`만 사용한다. 새 입장 애니메이션 방식에 맞춰 유지/정리를 결정한다.

### 4-7. 대표 프로젝트 (`featured` 통일)
- 메인에는 **`featured` 필드를 가진 프로젝트만** 보여준다. 현재 5개: rounz(1), muna(2), chromatic(3), klaybay(4), miral-payment(6). `featured.order` 순서로 정렬하며, 번호가 비어 있어도(5 없음) 문제없다.
- **표현 규칙:** `featured.order` 상위 2개(현재 rounz, muna)는 **액자**, 나머지(chromatic, klaybay, miral-payment)는 **벽의 폴라로이드**. 바꾸고 싶으면 `featured.order`만 조정한다.
- Hero 내부에 배치하므로 Hero 아래의 별도 Featured 영역은 만들지 않는다.
- `Home.tsx`의 `projectPreviewIds`와 `ProjectPreviewList`는 메인에서 제거한다. 컴포넌트 파일은 `/projects` 등에서 쓸 가능성을 확인한 뒤 삭제 여부를 결정한다. 사용 중이 아닌 `FeaturedProjectList`도 같은 방식으로 정리한다.
- 전체 목록은 `/projects`로 연결한다(Hero의 View Projects CTA 유지).
- 대표 프로젝트는 4~6개를 넘기지 않는다.

### 4-8. 접근성과 모바일
- 물건과 폴라로이드는 모두 키보드로 선택(Enter)해 열 수 있어야 한다. 드래그는 보조 수단이다.
- `prefers-reduced-motion`에서는 물리/바운스/입장 애니메이션을 줄이거나 끈다.
- 모바일: 터치 드래그와 페이지 스크롤이 충돌하지 않게 드래그 가능한 요소에만 `touch-action`을 지정한다. 좁은 화면에서는 아이템 수/크기/기본 배치를 별도로 정의한다(정돈 상태를 기본으로).
- 이미지: 배경 제거 PNG/WebP, 물건당 용량 관리, `next/image` 사용.
- SEO: `h1`과 소개 문구는 DOM에 유지하고, 정보 패널 내용은 목록 보기에서도 접근 가능하게 한다.

### 4-9. 전체 톤: 따뜻한 크림

- **방향:** 벽/배경은 따뜻한 크림, 선반과 포인트는 월넛 브라운, 텍스트는 순흑 대신 짙은 웜 브라운/차콜. 강조색은 물건 사진에서 하나만 골라 쓴다(예: 화분의 그린 또는 실뭉치 색. Phase 1 이미지 확정 후 결정).
- **기존 토큰 처리** (`globals.css`, `tailwind.config.js`): 아래 표는 방향이며, 실제 색값은 크림 벽 이미지와 나란히 놓고 Phase 2에서 확정한다.

|---|---|---|
| `--color-primary*` | 바이올렛 `#8758e8` 계열 | 브라운/포인트 계열로 교체 |
| `--color-secondary*` | 핑크 `#e86a9a` 계열 | 포인트 1색으로 정리하거나 제거 |

- **영향 범위(코드 확인):** 토큰을 쓰는 컴포넌트가 많아 토큰 교체만으로 대부분 따라온다. 다만 색상 값이 직접 들어간 곳은 수동 정리가 필요하다: `Skill.tsx`(색상 값 13곳), `ProjectCard.tsx`(2곳), `bg-[#...]` 같은 임의 색 클래스(약 16곳), `MainAnimation.module.css`(24곳, Hero 교체 후 미사용). 작업 전에 `grep`으로 목록을 뽑아 확인한다.
- **폰트:** 본문은 Satoshi + Pretendard 유지. 한글 손글씨체를 폴라로이드 키워드와 일부 포인트 문구에 추가한다.
- 크림 톤은 Hero만이 아니라 `/projects`, 프로젝트 상세, `/notes`까지 같은 토큰으로 적용한다. 컨셉이 섞이는 문제를 막기 위해 일부 페이지만 먼저 바꾸는 방식은 피한다.

## 5. 이미지 제작 방식
이번 구성에서 **AI/촬영 이미지가 필요한 것은 물건 3개(실뭉치, 핸드크림, 스킨답서스 화분)와 선반 판 1종**이다. 폴라로이드는 CSS 프레임 + 기존 프로젝트 이미지로 만들 수 있다. 벽은 CSS 단색/약한 그라디언트로 충분하다.

1. 직접 가진 물건(실뭉치/식물 등) 하나를 촬영한다.
2. 같은 사진을 여러 스타일로 변환해 비교한다: 배경만 제거한 실사 / 부드러운 3D 클레이 / 수채화풍 일러스트.
3. 스타일 하나를 확정하고 **프롬프트와 결과 이미지를 `public/shelf/_style/` 또는 `docs/`에 기준으로 저장**한다.
4. 나머지 물건은 같은 프롬프트와 기준 이미지를 넣어 같은 톤으로 만든다. 직접 촬영이 어려운 물건은 기준 이미지를 함께 넣어 생성. 핸드크림은 튜브 디자인(브랜드 로고 등)이 보이지 않는 무지 튜브나 직접 디자인한 라벨로 만든다.
5. 통일 규칙: 조명 방향, 카메라 각도, 그림자, 여백, 배경 투명.
6. **선반 판:** 3번 이미지 같은 월넛 판 한 종을 투명 배경 PNG/WebP로 만든다(촬영, AI 생성, 또는 나뭇결 텍스처를 CSS로 입히는 방식 중 Phase 1에서 비교). 길이는 가변이어야 하므로 가로로 늘리거나 반복해도 결이 자연스러운지 확인한다. 선반 아래 그림자는 CSS로 처리한다.
7. 폴라로이드가 사진 질감인 만큼, 물건이 일러스트/클레이 스타일이면 톤이 어긋날 수 있다. 스타일 확정 시 폴라로이드와 함께 놓고 확인한다.

## 6. 상세 페이지 개편안
- `ProjectHeader`에 **TL;DR + 역할/기간/팀 요약**을 추가.
- 데스크톱에서 **고정 목차**(스크롤 위치에 따라 활성화).
- MDX 섹션 표준: `TL;DR → Background → Problem → Process(결정과 trade-off) → Result → Reflection`. 프로젝트별로 없는 섹션은 생략.
- 선택 컴포넌트: `<Decision>`(번호 + 제목 + 설명), `<Insight>`(인용 + 출처), `<Changed>`("바뀐 점" 강조 박스).
- 폴라로이드에서 이어지는 진입이므로 상세 페이지 상단에도 같은 키워드/사진 톤을 이어 쓸지 검토한다.

10. 기술 스택 + 소프트스킬 물건: 기본안은 핸드크림. 꽃병 등 다른 물건으로 바꾸고 싶은지.

## 10. Claude Code 작업 요령
- 이 문서를 기준 문서로 두고, 핵심 규칙(컨셉, 토큰, 모션 규칙)을 `CLAUDE.md`에 요약한다.
- 레퍼런스는 스크린샷으로 전달하고 "무엇을 참고할지"(질감 / 모션 / 레이아웃)를 한 줄로 명시한다.
